# 木版年画刻版工序档案

## 项目简介

面向木版年画作坊的纯前端工序档案应用。它把画稿、分版、刻版、修版与套色印制过程串成可追溯的本地记录，便于刻工与印制管事按套色序号协作。

## Docker 一键启动

首次启动先复制环境配置，再构建并启动容器：

```bash
cp .env.example .env && docker compose up -d --build
```

停止服务可执行：

```bash
docker compose down
```

## 数据存储说明

数据全部写入浏览器 IndexedDB，不依赖后端服务。数据库名为 `gbwoodprint-db`，当前结构版本为 `3`。

- `version(1)` 建立画稿、版片、刻工、印制批次、工序节点五张表及常用查询索引。
- `version(2)` 为各表回填 `schemaRev: 2`，便于后续迁移识别数据结构。
- `version(3)` 返修放行：版片新增 `rev` 乐观锁版本号与「返修中」状态；印制批次新增 `releaseStatus`、`blockSnapshots`、`releaseBasis`，登记时保存四块版片当时的状态与崩口记录。历史批次（含内置三批）迁移为「待复核」，原印数、每版印次与套色偏差一律不改写。
- 首次创建数据库时通过 Dexie 的 `populate` 回调写入四类画稿、完整基础版片、四名刻工、印制批次与多条工序节点。
- 刷新页面不会丢失数据；清除浏览器站点数据会同时清除本地档案。

## 返修放行规则

- 新批次登记只在四块版片全部为「已刻成」或「已修版」时放行；放行批次逐块保存版片状态、崩口记录与版本快照作为依据。
- 版片崩口返修流程：在版片编排台点「崩口返修」，版片转为「返修中」、挂到修版刻工名下（计入在刻数），画稿可印结论立即失效；修版完成后在同一行提交修版人、耗时与修版记录，系统在一笔事务内追加修版节点、版片转「已修版」、同步刻工在刻数并重算画稿可印结论。
- 版片每次状态/崩口/色序变更都会自增 `rev`。两个标签页同时提交时，后提交一方的事务在提交时重读版片版本，版本不符即报冲突并整笔回滚，不会覆盖前一次的版片与节点记录；写入中途失败同样整笔回滚，不留下半套状态。
- 标签页之间通过 BroadcastChannel（不可用时降级为 storage 事件）实时同步档案。

## 核心功能与路由表

| 路由 | 页面 | 主要能力 |
| --- | --- | --- |
| `/drafts` | 画稿总览 | 按题材与状态筛选，查看版片刻成进度和最近印制批次，内联新建画稿 |
| `/drafts/:id/blocks` | 版片编排台 | 按套色序号排列表格，指派刻工、校验序号、标记刻成并记录崩口 |
| `/blocks/:id/nodes` | 工序节点时间线 | 推进或回退工序节点，登记操作人、时间与耗时 |
| `/batches` | 印制批次登记 | 登记纸张、颜料、印数，并逐版填写套色偏差 |
| `/carvers` | 刻工档与版片分布 | 按专长筛选，查看在刻版片数、节点平均耗时与当班分布 |
| 其它 | 画稿总览 | 已实现 history 路由到画稿总览的回退 |
